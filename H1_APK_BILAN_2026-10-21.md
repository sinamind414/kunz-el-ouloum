## DÉCOUVERTE MAJEURE — contamination des builds locaux par `.env`

Un `.env` local (non commité, ignoré par git — vérifié `git check-ignore`) contenait
`NODE_ENV="development"`. Vite (6.4.3) applique cette valeur AUSSI AU BUILD :
chaque `npm run build` local produisait un bundle **en sémantique dev** :
- `import.meta.env.PROD` replié à `false` → le bloc d'enregistrement du Service
  Worker (`src/main.tsx`) éliminé du bundle ;
- transformations JSX en mode dev (`jsxDEV`) — **40 chunks sur 82**.

**Portée** : builds LOCAUX uniquement. Les builds CI (GitHub) ne voient pas ce
fichier — les déploiements en production ont toujours eu `PROD=true`
(run 246 : SUCCESS ; antériorité R2 audit 2026-10-15 confirmée côté réel).

**Correctif** (préservation serveur vérifiée avant retouche) : la ligne est
commentée dans `.env` (réversible). Côté serveur : `server.ts:606`
`process.env.NODE_ENV !== "production"` prend la même branche avec `undefined`
qu'avec `"development"` ; `/healthz` retombe sur `|| "development"` — **zéro
changement de comportement**.
